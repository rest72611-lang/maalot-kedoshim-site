# הסרת מדיה מהאתר לעומת מחיקה מהיסטוריית Git

המסמך מסביר מה באמת קורה לתמונה או ל־PDF כשמסירים אותם מהאתר, ולמה **הסרה מהאתר** איננה **מחיקה**.

- **✅ קיים**: מתאר את המצב היום, שבו כל המדיה נמצאת במאגר הזה.
- **🔜 מתוכנן**: מתאר את המצב אחרי שתתווסף מדיה חדשה באחסון Cloudflare R2. ראו [ARCHITECTURE.md](../ARCHITECTURE.md).

---

## 1. איפה המדיה נמצאת היום ✅

כל המדיה של האתר נמצאת בתיקיית `assets/` במאגר הזה. המאגר **ציבורי**:

| תיקייה | מה יש בה |
|---|---|
| `assets/activity/` | תמונות גלריית הפעילות |
| `assets/notices/` | קובצי PDF של לוח המודעות |
| `assets/popup/` | קובצי PDF של מודעות הפופאפ |
| `assets/images/` | לוגו, שלט ו־QR (קבצים חובה) |
| `assets/donations/` | ה־PDF של סיפורי הישועה |

בזמן הבנייה הקבצים מועתקים או מומרים לתוך `dist/` ומתפרסמים ב־GitHub Pages.

---

## 2. הסרה מהאתר (מדיה ישנה) ✅

**איך מסירים:**
1. מוחקים את הקובץ מתיקיית `assets/` המתאימה, בענף נפרד.
2. פותחים Pull Request. הבדיקה `pr-checks` חייבת לעבור.
3. ממזגים ל־`main`. `deploy.yml` בונה ומפרסם את האתר מחדש.

**מה קורה אחרי זה:**
- הקובץ **כבר לא מוצג באתר**, והכתובת שלו באתר מחזירה 404.
- הקבצים שמתגלים אוטומטית (`activity`, `notices`, `popup`) נעלמים מהעמוד בלי לשנות קוד.
- קבצים ב־`assets/images/` וב־`assets/donations/` הם **קבצים חובה**. מחיקה שלהם תכשיל את הבנייה, ולכן החלפה שלהם מחייבת גם שינוי בקוד.

**מה עדיין קיים אחרי ההסרה:**

| איפה | עד מתי |
|---|---|
| **היסטוריית Git**: כל commit קודם עדיין מכיל את הקובץ, ואפשר להוריד אותו מ־GitHub דרך commit ישן | **לתמיד**, אלא אם משכתבים היסטוריה (סעיף 3) |
| **עותקים מקומיים של המאגר** (clones ו־forks) | לתמיד; אין עליהם שליטה |
| **artifact של בדיקת PR** (`site-dist-pr-<N>`) | עד שתוקפו פג (7 ימים) |
| **מטמון של דפדפנים ושל ה־CDN של GitHub Pages** | דקות עד שעות |
| **מנועי חיפוש וארכיוני אינטרנט** | לפי המדיניות שלהם; לא בשליטתנו |

> **לסיכום:** הסרה מהאתר מונעת מהמבקרים **לראות** את הקובץ באתר. היא **לא** מוחקת אותו מהעולם.

---

## 3. מחיקה מהיסטוריית Git — לא מתוכננת

כדי למחוק קובץ מההיסטוריה צריך **לשכתב את ההיסטוריה של המאגר**, למשל עם `git filter-repo`, ואחר כך לבצע force-push.

**למה זה לא מתוכנן:**
- **ההגנה על `main` חוסמת force-push** (GitHub Ruleset). כדי לבצע שכתוב צריך לבטל זמנית את ההגנה.
- **כל ה־commits משתנים.** קישורים ל־commits ול־Pull Requests קיימים נשברים, וכל עותק מקומי צריך להיות מוחלף.
- **זה לא מוחק עותקים שכבר יצאו מהמאגר:** forks, clones, מטמונים וארכיונים.
- **ב־GitHub, ניקוי מלא** של תצוגות שנשמרו במטמון עשוי לדרוש פנייה לתמיכה של GitHub.

**ההחלטה:** מדיה ישנה **תוסר מהאתר בעת הצורך, בלי שכתוב של היסטוריית Git.**

**ההשלכה המעשית:** לפני שמוסיפים למאגר הציבורי קובץ כלשהו, צריך להניח שהוא **יישאר ציבורי לתמיד**.

## 4. מדיה חדשה ב־R2 🔜

> סעיף זה מתאר תכנון. הוא עדיין לא ממומש.

| | מדיה ישנה (במאגר) | מדיה חדשה (R2) 🔜 |
|---|---|---|
| איך מתווספת | commit ו־build | אישור הצעה; בלי commit ובלי פריסה |
| איך מוסרת | מחיקה ב־commit (סעיף 2), או הסתרה מממשק הניהול 🔜 | **מחיקה קבועה** מממשק הניהול |
| נשאר עותק אצלנו? | כן, בהיסטוריית Git | לא. הקובץ נמחק מהאחסון, והכתובת מחזירה 404 |
| נשאר עותק במקום אחר? | כן (סעיף 2) | ייתכן: מטמון דפדפן, ומי ששמר את הקובץ, וגם ההודעה המקורית ב־WhatsApp |

**הסתרה 🔜:** ממשק הניהול יאפשר להסתיר פריט של מדיה ישנה מהתצוגה באתר, בלי commit ובלי פריסה. הקובץ עצמו יישאר במאגר ובהיסטוריה שלו, בדיוק כמו בסעיף 2.

**מחיקה קבועה 🔜:** מוחקת מהאחסון את הקובץ ואת כל הגרסאות שנוצרו ממנו (למשל הקטנות). זו מחיקה אמיתית מהאחסון שלנו, אבל גם היא לא יכולה לבטל עותקים שכבר נשמרו מחוץ למערכת.
